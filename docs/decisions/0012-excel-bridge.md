# 0012: Excel bridge (P4.1 spike)

Date: 2026-10-16. Step: P4.1.

## Decision

A task-pane Office.js add-in lives in `integrations/excel-addin`; Gestura main hosts a
loopback HTTPS + WebSocket bridge in `apps/desktop/src/main/excel-bridge`. The add-in is
the only process that touches the Office.js object model. Main is the only process that
holds an ActionGate `ConfirmedAction`; the add-in never authors a write. All frames crossing
the socket are validated against the shared zod schemas in `packages/core/src/excel.ts`.

The bridge serves the add-in pages from `https://localhost:<port>` over a self-signed cert
(`selfsigned`) persisted under `userData/excel-dev-cert` so the human trusts it once per
platform (macOS Keychain / Windows cert store). No third party hosts the add-in. A
per-session pairing token is generated by main, injected into the served HTML server-side at
the `%%GESTURA_PAIRING_TOKEN%%` placeholder, and required on every WebSocket upgrade
(constant-time compare). The add-in reconnects with capped backoff after Excel restarts and
reloads the page.

## Messages

- `getContext` → `context` event: `{ sheetName, selectionAddress, activeCell, headers,
  columnTypes, usedRangeAddress }`, plus `samples` (up to 5 values/column) only when the
  server's `shareSampleValues` flag is on (Q15 default: off).
- `writeFormula(ConfirmedAction)` → `done`: writes `range.formulas` to the target cell. The
  main-process `ExcelBridge.writeFormula` rejects anything that is not a fresh, unused
  ActionGate confirmation for `kind: 'formula'` (bounded age, single-use). The add-in never
  receives a write command it did not originate from a confirmed action.
- `selectRange(address)` → `done`: calls `range.select()` only — it changes the selection and
  never writes. Its address is validated against `CellRangeSchema`.

## Ctrl+Z behavior

`range.formulas` / `range.values` writes mutate the workbook document model and enter Excel's
undo stack, so Ctrl+Z is expected to undo an add-in formula write exactly as it would a typed
formula. `range.select()` changes only the selection, which is not part of the undo stack —
consistent with `selectRange`'s "never writes" contract. These are documented Office.js
semantics; the spike sandbox has no Office host, so a live undo check in desktop Excel is a
manual step and remains unverified here.

## Coverage and limitations

Both webviews must open a WSS socket to `127.0.0.1` with a self-signed cert. WebKit (macOS)
and WebView2 (Windows) are expected to permit this once the cert is trusted; if a platform
rejects the loopback TLS socket despite a trusted cert, the documented fallback is to serve
the taskpane over plain `http` on loopback (the server already falls back to `http` when no
TLS is supplied) and keep the token requirement. Live verification on both platforms is a
manual step; only the macOS/Node `ws` path is exercised by the automated tests.

Headers are detected only when the first row is text-shaped and non-empty. Column types are
coarse inference (`string`/`number`/`boolean`/`date`/`error`/`empty`/`mixed`), not Excel cell
format metadata. Sample values are stripped to strings and capped at 5 per column, behind the
opt-in toggle.

## Scaffolding and sideloading

The add-in is hand-scaffolded as a minimal manifest + taskpane rather than generated with
`yo office` (the current Yeoman `generator-office`), which is interactive and heavyweight for a
spike. Sideloading is the standard per-platform path: on Windows use the "My Add-ins" /
shared-folder catalog or `office-addin-debugging start manifest.xml`; on macOS use the
`WeF` web add-in folder or the "Insert → Add-ins → My Add-ins" catalog. The manifest points
`SourceLocation` at `https://localhost:3510/taskpane.html` and declares `AppDomains`
`https://localhost:3510`; the cert must be trusted first. The live generator/sideload steps
were not re-verified online in this sandbox (no web access); treat these as the known-current
approach and confirm against Microsoft's current docs before the human sideloads.

## Sources checked

- [Office.js `Excel.run` / `Range.formulas` / `Range.select`](https://learn.microsoft.com/en-us/javascript/api/excel) — host object model used by the add-in.
- [Office Add-ins manifest (task pane)](https://learn.microsoft.com/en-us/office/dev/add-ins/reference/manifest) — `TaskPaneApp` manifest with `SourceLocation`, `AppDomains`, `ReadWriteDocument`.
- `selfsigned` bundled types — SAN must be supplied inside `extensions` as `{ name: 'subjectAltName', altNames: [...] }`.

No new third-party package beyond `ws` and `selfsigned` (desktop) and `@types/office-js` +
`esbuild` (add-in). `ws` is already a desktop dependency; `selfsigned` is added for the dev
cert. All new schemas live in `packages/core`, shared by both sides.
